# Education app DocType field guide

This guide summarizes the **83 DocTypes defined by the Education app**. It lists their business fields and the main purpose of each record, organized by workflow so related records are easier to understand.

Source definitions: [`education/education/doctype`](../education/education/doctype). Field names and relationship targets are taken from each DocType JSON definition. Frappe-managed metadata fields and visual form-layout fields (sections, columns, and tabs) are omitted.

## Reading the tables

- `Link → DocType` refers to another record.
- `Table → DocType` contains child rows owned by this DocType.
- **Record**, **Submittable**, **Single**, and **Child row** describe the DocType behavior defined by Frappe.
- Fields are shown as `fieldname (Label): Type`; Link and Table fields include their target DocType.
- Links identify app-level relationships; they do not necessarily imply database foreign-key constraints.

## How the main records fit together

1. **Academic Year** contains **Academic Terms**. A **Program** (such as a standard/class) defines its Courses.
2. A **Student Applicant** can become a **Student**. Student profile records can include guardians and sibling rows.
3. **Program Enrollment** connects a Student to a Program and academic period. It may list Program courses and fees; submission creates related Course Enrollments.
4. **Student Groups** gather students and instructors for academic activities. Course Schedules connect groups, courses, rooms, and instructors.
5. **Assessment Plans** define criteria and schedules. **Assessment Results** record scores and grades using a Grading Scale.
6. **Fee Structures** define charges; **Fee Schedules** apply charges; **Fees** hold student billing records; **Payment Records** track payment details.

### Promotion note

Promotion is represented by creating another **Program Enrollment** for the next Program and academic year. The Program Enrollment Tool selects students from a source Program/year and creates destination enrollments. It has no assessment-result/pass-fail eligibility field, so failed students are not automatically blocked by this tool.
